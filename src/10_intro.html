Go: orientación a objetos sin clases

Los patrones GoF se escribieron pensando en C++/Smalltalk. En Go se expresan con otras herramientas

// 1. struct = datos (el "estado" del objeto)
type Animal struct {
    Nombre string
}

// 2. Método = función con receptor
func (a *Animal) Presentarse() string {
    return "Soy " + a.Nombre
}

// 3. Interfaz = contrato. Se implementa IMPLÍCITAMENTE:
//    basta con tener los métodos (no existe "implements")
type Hablador interface {
    Hablar() string
}

// 4. Embedding = composición que "promueve" métodos
type Perro struct {
    Animal        // Perro obtiene Presentarse()
    Raza   string
}

func (p *Perro) Hablar() string { return "¡Guau!" }

// 5. Funciones de primera clase
type Saludo func(string) string

func main() {
    p := &Perro{Animal{"Firulais"}, "Criollo"}
    var h Hablador = p            // Perro satisface Hablador
    fmt.Println(p.Presentarse(), h.Hablar())
}

Proverbio de Go

"Acepta interfaces, devuelve structs" y "cuanto más grande la interfaz, más débil la abstracción". Verás estas dos ideas en casi todos los patrones.
